## 🚀 Deployment

### Automatic Deployment

The app automatically deploys to GitHub Pages when changes are pushed to the `main` branch via GitHub Actions.

**Workflow file:** `.github/workflows/deploy.yml`

### How Redeployment Works

1. Push changes to the `main` branch
2. GitHub Actions automatically:
   - Sets up Flutter
   - Runs `flutter pub get`
   - Builds the web app with `flutter build web --base-href /flutterfriday/ --release`
   - Deploys to GitHub Pages

3. The site updates at https://fx0628.github.io/flutterfriday/ within a few minutes

### Base HREF Configuration

The app is built with `--base-href /flutterfriday/` to work correctly as a GitHub Pages project site.

- **Project site:** https://fx0628.github.io/flutterfriday/ (current setup)
- If migrating to a user site (https://fx0628.github.io/), change `--base-href` to `/` in `.github/workflows/deploy.yml`

### Manual Deployment

To manually trigger deployment:

1. Go to the [Actions tab](https://github.com/fx0628/flutterfriday/actions)
2. Select "Deploy Flutter Web to GitHub Pages"
3. Click "Run workflow"

## 🛠️ Local Development

```bash
# Get dependencies
flutter pub get

# Run in development mode
flutter run -d chrome

# Build for production
flutter build web --release
```

## 📦 Build Artifacts

The `build/` directory is gitignored (as per Flutter best practices). Build artifacts are generated by GitHub Actions during deployment and are not committed to the repository.

## 🔧 GitHub Pages Setup

GitHub Pages is configured to deploy from GitHub Actions:

1. **Repository Settings** → **Pages**
2. **Source:** GitHub Actions
3. **Build and deployment:** GitHub Actions workflow
